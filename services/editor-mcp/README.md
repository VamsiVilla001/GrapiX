# Editor MCP

Run `cargo run -p gx-editor-mcp -- --root <project-store-folder>` to expose
the Editor's authoring tools over MCP on stdio. Configure a client to launch
the built `gx-editor-mcp` binary with those two arguments. The launching
process grants access to that project-store root; the server has only the
Author scope and no Program-control connection.

Add `--http <port>` to serve stateless streamable HTTP instead, on
`127.0.0.1:<port>` and nothing else (`0` picks a free port; the bound URL is
printed on stderr). The endpoint is `/mcp`. `Host` must be `127.0.0.1` or
`localhost`, and a request carrying any browser `Origin` is refused: the
clients are local agents, not web pages.

The wire is the official Rust SDK, rmcp (build plan 8.14). It speaks the
2026-07-28 revision, where there is no `initialize` and each request carries
`_meta` with `io.modelcontextprotocol/protocolVersion` and
`io.modelcontextprotocol/clientCapabilities` (over HTTP, also the
`MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` headers), and the
2025-06-18 revision with its handshake. A client naming any other revision
in `initialize` is answered 2025-06-18.

A tool's value travels as `structuredContent`, with one text content block
holding the same JSON. A refusal is a JSON-RPC error, code -32000, with the
structured refusal in `data`. The scope gate runs before every handler on
both transports; an author token never reaches an operator tool.

`tools/list` advertises installed handlers, with `inputSchema` generated from
the Rust types the handlers parse. The same schemas are checked in under
`Shared/generated-ts/schemas/mcp/` and regenerated by `npm run codegen`.
Each listed tool also carries its registry entry (group, effect, required
scope, contract types) under `_meta["dev.grapix/tool"]`.

Without an engine capability exchange, this standalone process declares no
material support to preflight. It does not invent renderer capabilities.
